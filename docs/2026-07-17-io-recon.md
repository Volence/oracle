# I/O + controller recon-lite — the $A10000–$A1001F register block and the 3-button pad protocol

**Status: RECORDED 2026-07-17.** Grounds the controller/I/O push (the last piece before a real ROM can
poll its pads for a title screen). Push B already made the **version register at `$A10001`** live
(`bus::MD_VERSION = 0xA0`, byte-decoded in `MegaDriveBus::mapped_byte`); the rest of the block
(`$A10003–$A1001F`) is currently a **stub** that reads `0` and drops writes. This doc pins the byte formats
and the 3-button pad TH protocol that the real block must implement, so the wiring is trace-to-pins, not
guesswork.

**Permitted sources only** (audit policy 3, identical to the VDP recon docs): official Sega documentation
(Genesis Software Manual — segaretro.org / archive.org scans), **Plutiedev** (plutiedev.com — the I/O-ports
and controllers pages), SpritesMind forum hardware-test threads. **No emulator source was opened**
(BlastEm / jgenesis / Genesis Plus GX). Where a fact appears only in an excluded third-party doc it is
treated as not-pinnable, not cited.

Items are numbered **IO1–IO6**. Each states the pin, the evidence, confidence, the behavioral-vs-timing
class (per `docs/reference/README.md` and the timing-vs-behavior rule), and the open remainder with its
pin-vs-defer disposition.

## IO1 — The register map ($A10000–$A1001F)

**PINNED.** The I/O controller exposes 16 byte-wide registers, each on data lines **D0–D7** and therefore
at an **odd** byte address within the word-addressed space (an even byte in the range reads the unmapped
high half). Three ports — **Port 1** (player 1), **Port 2** (player 2), **EXP** (the modem/EXT connector) —
each get a parallel triplet (Data / Control) and a serial triplet (TxData / RxData / S-Control):

| Address | Register | Address | Register |
|---|---|---|---|
| `$A10001` | Version | | |
| `$A10003` | **Port 1 Data** | `$A10009` | **Port 1 Control** |
| `$A10005` | **Port 2 Data** | `$A1000B` | **Port 2 Control** |
| `$A10007` | **EXP Data** | `$A1000D` | **EXP Control** |
| `$A1000F` | Port 1 TxData | `$A10011` | Port 1 RxData |
| `$A10013` | Port 1 S-Control | `$A10015` | Port 2 TxData |
| `$A10017` | Port 2 RxData | `$A10019` | Port 2 S-Control |
| `$A1001B` | EXP TxData | `$A1001D` | EXP RxData |
| `$A1001F` | EXP S-Control | | |

**Evidence**: Plutiedev "Mega Drive I/O ports" (plutiedev.com/io-ports) gives the full parallel table
(P1 Ctrl `$A10009` / Data `$A10003`; P2 `$A1000B`/`$A10005`; EXT `$A1000D`/`$A10007`) and the serial table
(P1 S-Ctrl `$A10013`, RxData `$A10011`, TxData `$A1000F`; P2 `$A10019`/`$A10017`/`$A10015`; EXT
`$A1001F`/`$A1001D`/`$A1001B`). Corroborated by the Genesis Software Manual peripheral-I/O section.
**Confidence**: high. **Classification**: behavioral (which address is which register). **Open remainder**:
none.

## IO2 — Control (direction) register semantics

**PINNED.** Each Control register is a per-pin **direction** register for the 7 I/O pins of its port, plus
an interrupt-enable in the top bit:

- **Bits 6–0**: pin direction. **`0` = input** (the pin is read from the peripheral), **`1` = output**
  (the console drives the pin to the peripheral). Bit *n* of Control governs bit *n* of that port's Data
  register.
- **Bit 7**: **TH-interrupt enable** (when set, a TH transition on the port raises the external interrupt,
  level 2). Not consumed this push — see IO6.
- **Power-on default = `$00`** (every pin an input; the port floats high through its pull-ups until a game
  configures it).

**Evidence**: Plutiedev "Mega Drive I/O ports": *"Writing a 0 sets the pin to input (from peripheral), 1
sets the pin to output (to peripheral). Bits 6–0 each control one of seven pins. Bit 7 enables external
interrupts when set to 1."* **Confidence**: high. **Classification**: behavioral. **Open remainder**: the
TH-interrupt (bit 7) delivery path is deferred (IO6).

## IO3 — Data register read / write model (the load-bearing pin)

**PINNED.** The Data register is where the console reads the peripheral. The model, per pin *i*:

- **Write**: sets the latch for every bit. Only pins configured as **outputs** actually drive the wire; the
  latched value of input pins is retained but not driven. (Modelling all 8 latch bits is harmless and
  matches a game re-reading a value it wrote to an output pin.)
- **Read** returns, **bit by bit**: for an **output** pin the driven (latched) value; for an **input** pin
  the value the peripheral is currently presenting on that wire. As a mask expression:

  ```
  read = (latch & ctrl) | (device_input & !ctrl)
  ```

  where `ctrl` is the port's Control register and `device_input` is the byte the attached peripheral drives
  (IO4). A wire configured as input with nothing driving it floats **high** (pull-up → reads `1`).

**Evidence**: Plutiedev "Mega Drive I/O ports": *"Writing to the data port changes the values of the pins
that have been set as outputs (the rest are ignored)… Reading back from the data port returns the current
values of all pins (both input and output)."* The output-pin-reads-back-the-latch and input-pin-reads-the-
device split is the universal documented model (Genesis Software Manual; it is the whole basis of the TH
select protocol in IO4 — the game drives TH as an **output** and reads the other six as **inputs**).
**Confidence**: high. **Classification**: behavioral. **Open remainder**: the real open-collector case
where a *pressed button pulls an output-high pin low* is **not** modelled — output pins always read back the
latch. No game relies on the pull-down (they drive TH only and read the rest as inputs); documented as an
intentional simplification, not a divergence a consumer can observe.

**AMENDED 2026-09-19 (`F-TH-PULLUP-UNDISCRIMINATED`, `docs/2026-09-19-th-pullup.md`). The pull direction
stands, and the citation above never covered it.** The follow-up asked whether *"a wire configured as input
with nothing driving it floats high"* was ever grounded. It was not: the Plutiedev quote in this item is
accurate for the read/write **model** and **says nothing about which way an undriven pin floats** — the word
*pull* appears on `plutiedev.com/io-ports` only in its two sentences about Control **bit 7**, the
TH-interrupt enable, and `plutiedev.com/controllers` does not contain it at all. IO2's parenthetical
(*"floats high through its pull-ups"*) and IO4's bit-7 table row were uncited for the same reason. **Three
statements of the pull rested on one unattributed clause.** It is now grounded four ways, and the strongest
is a mechanism rather than an assertion:

* **The pad pulls TH high itself.** Hardware teardowns of the 3-button pad: *"One additional connection is a
  pull-up resistor on the select line. If it is left unconnected it will be 'pulled' high"*, and the button
  switches sit on 10K pull-ups to 5 V, shorting to ground when pressed (`SukkoPera/MegaDrivePlusPlus` wiki;
  corroborated by the U. Alberta CMPE 490 controller app note and the `jonthysell/SegaController` wiki).
  The select line *is* TH: with the console leaving TH an input (high impedance), the **pad's own** resistor
  holds it at 5 V and the `74HC157` presents the TH-**high** nibble. The console's internal pull is not even
  load-bearing for the case that matters. These are hardware references outside this doc's permitted-source
  list — recorded as corroborating **mechanism**, not as the pin.
* **The permitted source does say it, on a different page-section.** Plutiedev "Controllers", *Checking if
  there's a controller*: *"If there's nothing in the port it should look as if no buttons are pressed … look
  at bits 3-2 from the second step: they **should be `00`**. If they aren't, then it means there isn't a
  controller plugged in."* Buttons are active-low (IO4), so *"looks as if no buttons are pressed"* is
  *"undriven pins read `1`"*. About D2/D3 rather than TH, but the same seven pins of the same port.
* **An independent model agrees.** `tools/blastem-differential/th_pullup.bin` through BlastEm 0.6.2 reads
  bits 6–0 of `$A10003` as `$7F` with Control pristine at `$00`, on both ports, with both controls firing
  (driven high `$7F`, driven low `$33`) and the latch-echo confound excluded. Corroboration, **not
  hardware** — two models can inherit one documentation error.
* **A corpus row already depended on it.** Under an inverted-pull mutation `vdp_sprite_masking`'s H40 half
  never arrives (`pc: 790` = `$000316`, its `btst #5,$A10003`), reddening two `conformance_roms` tests.

**Confidence: high** (was: high, uncited). **The remainder is real hardware** — nothing here is a
measurement on a console; `th_pullup.bin` is committed and needs only a way to read work RAM back. **Tagged
for a foreground follow-up.** The open-collector simplification above is unchanged. The direct in-tree gate
is `undriven_th_reads_high_in_both_models` in `crates/oracle-core/tests/io_controllers.rs`, whose
expectations are BlastEm's recorded bytes, not our own output.

## IO4 — The 3-button controller TH protocol

**PINNED.** A standard 3-button Mega Drive pad is read by toggling **TH = bit 6** of the Data register (the
game drives it as an output via Control `$40`) and reading the other six pins as inputs. Buttons are
**active-low**: a pressed button reads **`0`**, a released button reads **`1`**. The peripheral drives two
different nibble sets depending on the TH line it sees:

| Bit | TH = 1 (game wrote `$40`) | TH = 0 (game wrote `$00`) |
|---|---|---|
| 7 | 1 (pull-up, undriven) | 1 (pull-up, undriven) |
| 6 | TH (echoes the driven line) | TH (echoes the driven line) |
| 5 | **C** | **Start** |
| 4 | **B** | **A** |
| 3 | **Right** | **0** (forced low) |
| 2 | **Left** | **0** (forced low) |
| 1 | **Down** | **Down** |
| 0 | **Up** | **Up** |

The **bits 3–2 forced to `0` when TH = 0** is the classic detection signature that distinguishes a Mega
Drive pad from a Master System pad. TH (bit 6) is an output on a normal read, so its read-back value comes
from the latch via IO3; the peripheral does not drive it.

**Evidence**: Plutiedev "Controllers" (plutiedev.com/controllers): write `$40` → *bit5 C, bit4 B, bit3
Right, bit2 Left, bit1 Down, bit0 Up*; write `$00` → *bit5 Start, bit4 A, bits3–2 always read 0, bit1 Down,
bit0 Up*; *"A bit = 1 means the button is not pressed, a bit = 0 means it's pressed"* (active-low); *"Write
$40 to both the control port and data port during initialization."* Corroborated by the Genesis Software
Manual controller section. **Confidence**: high. **Classification**: behavioral (the exact byte a game
reads for a given button state). **Open remainder**: the 6-button extension (IO6).

**AMENDED 2026-09-19: bit 7 is NOT settled — `F-IO-DATA-BIT7`.** The table's *"7 — 1 (pull-up, undriven)"*
row is the one claim here that the quoted evidence does not contain, and an independent model disagrees with
it. The port has **seven** I/O pins (Control is bits 6–0; its bit 7 is the TH-interrupt enable, IO2), so no
pin corresponds to Data bit 7 at all. `pad_device_byte` forces it to `1` unconditionally; **BlastEm 0.6.2
hands back the Data latch's own bit 7** — `0` until a ROM writes a `1` there, then `1`, independently of
Control (measured at observables +10/+11 of `th_pullup.bin`; see `docs/2026-09-19-th-pullup.md`). So our core
answers `$FF` where BlastEm answers `$7F` on any pad read that has not first latched bit 7, which is every
pad read a normal game performs. **Neither side is corroborated**: Plutiedev's I/O-ports and Controllers
pages never mention the register's bit 7, and the MegaDrive wiki's `315-5309` page contradicts itself
(*"PD7: Unused. Should be set as 0"* followed immediately by *"PD7: /TH pin"*). **Booked, not fixed** — the
same standing as `known_differences.py`'s STOP×trace entry — and pinned by
`bit_7_of_the_data_register_is_a_recorded_divergence` so a change to our side is loud. Bits 6–0, including
the whole TH protocol and the forced bits 3–2, are unaffected and agree between the two models.

## IO5 — Version register ($A10001) — carried from Push B

**PINNED (already live).** `$A10001` reports console identity. Bit layout (MSB→LSB):

| Bit | Field | `0` | `1` |
|---|---|---|---|
| 7 | Region | Domestic (Japan) | Overseas (US/Europe) |
| 6 | Video | NTSC | PAL |
| 5 | Expansion | Sega CD / expansion attached | none attached |
| 4 | (reserved) | — | — |
| 3–0 | Hardware version | 0 | … |

`bus::MD_VERSION = 0xA0` = `1010_0000` = overseas + NTSC + no-expansion + hardware version 0 — the value
Push B froze and the export golden was frozen against. **This push does not change it.**

**Evidence**: Genesis Software Manual peripheral section (standard documented layout); the chosen value +
its provenance are recorded at `bus.rs::MD_VERSION`. **Confidence**: high. **Classification**: behavioral.
**Open remainder**: none for this push.

## IO6 — Deferred: 6-button pad, serial peripherals, TH interrupt, Z80 arbitration

Deferred, each with its pin source named so a later push starts from a pin, not a blank:

- **6-button controller** — the 3-button read is a prefix of the 6-button read; the extension counts TH
  **toggles** and, after the sixth edge, presents the X/Y/Z/Mode buttons, resetting the counter after a
  ~1.5 ms idle so the next frame starts clean (Plutiedev "Controllers", 6-button section: *"reads only once
  per frame … timing-dependent backwards compatibility"*). This adds **master-clock coupling** (the timeout
  reset) for **no Sonic-era consumer** — S1/S2/S3K/S&K are 3-button titles. **Deferred by explicit decision
  (see the plan).**
- **Serial registers (TxData / RxData / S-Control)** — the serial UART mode of each port. No serial
  peripheral (modem, link cable) is attached in a cartridge title, so they are **deterministic stubs** this
  push (the plan pins the exact stub behavior). Pin source when needed: Plutiedev I/O-ports serial section +
  Genesis Software Manual.
- **TH external interrupt (Control bit 7)** — level-2 autovector on a TH edge; used by the Menacer/light-gun
  and a few peripherals, not by pad polling. Deferred; pin source: Sega Software Manual interrupt section.
- **Z80 BUSREQ/RESET arbitration (`$A11100`/`$A11200`)** — **explicitly out of scope**; it lands with the
  Z80 core. The existing "bus granted / reset released" stub is unchanged.
