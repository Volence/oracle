### Event A — the shared fixture file (run 1, `8a25969`)

**What failed.** `every_declared_bound_is_refused_by_name_one_step_outside`, in
`cargo test --workspace`:

```
running 6 tests
test every_declared_bound_is_refused_by_name_one_step_outside ... FAILED
thread '...' (7766) panicked at crates/oracle-aether/tests/common/mod.rs:495:9:
emulator/load_symbols failed: {"code":-32602,"data":{"droppedEvents":0,"frame":0,"mclk":0,
  "path":"/tmp/oracle-rb-7764/probe.lst","running":false},
  "message":"/tmp/oracle-rb-7764/probe.lst is not a usable listing: no symbols found (n...
test result: FAILED. 5 passed; 1 failed; 0 ignored; 0 measured; 0 filtered out
error: test failed, to rerun pass `-p oracle-aether --test request_bounds`
```

**Mechanism, derived from the tree at the red SHA, not from a note.** At `8a25969`,
`crates/oracle-aether/tests/request_bounds.rs:492`:

```rust
fn load_probe_symbol(c: &mut Client) {
    let lst = format!("  Symbol Table ...\n {PROBE_SYMBOL} : FF0600 C |\n\n   1 symbols\n");
    let dir = std::env::temp_dir().join(format!("oracle-rb-{}", std::process::id()));
    std::fs::create_dir_all(&dir).expect("create the symbol fixture dir");
    let path = dir.join("probe.lst");                 // <-- ONE path, per PROCESS
    std::fs::write(&path, lst).expect("write the symbol fixture");
    c.ok("emulator/load_symbols", json!({"path": path.to_str().unwrap()}));
}
```

`load_probe_symbol` has exactly one caller, `client()` at `:474`, and `client(&h)` has **three call
sites — `:522`, `:635`, `:821` — three `#[test]` functions in one binary**, which cargo runs on
parallel threads. All three write the same path while all three servers read it, and `std::fs::write`
**truncates before it writes**. The server's read is a plain `std::fs::read_to_string`
(`crates/oracle-aether/src/engine.rs:7110`), so a read landing inside another thread's truncate
window returns **zero bytes**, and the parser refuses with a message about the file's *content* —
for a file whose content was correct a microsecond either side. The `-32602` payload names
`/tmp/oracle-rb-7764/probe.lst` and the panicking process is `7766`: two different pids in the same
run, which is the fixture directory being shared, not a stale leftover.

**FIXED-SINCE `3a7ec87`** — *"harness: a probe that never came back is a THIRD outcome, and a shared
fixture file is a race"*, 2026-09-09 16:37:35 −0400 = **20:37 UTC, after the 14:11 UTC red**.
Ancestry verified both ways with `git merge-base --is-ancestor`: `8a25969` → `3a7ec87` → `HEAD`.
The fix is a per-call counter on the filename:

```rust
static NEXT: std::sync::atomic::AtomicU32 = ...;
let n = NEXT.fetch_add(1, std::sync::atomic::Ordering::SeqCst);
let path = dir.join(format!("probe-{n}.lst"));
```

**This is a FIXED-SINCE with a mechanism, which is what RULE 1 requires** — and the mechanism is
readable off the pre-fix source without trusting the fix's own commit message. RULE 2 was not
reached: the red did not have to be reproduced, because the race is structural in the code as
written.

**Not reproduced by re-running, and the cost that decided it:** reproducing a truncate-window race
needs a loaded box and many trials at an old SHA, i.e. a build plus a loop per arm. The brief scoped
this row as log-only, the mechanism is visible statically, and the counter fix removes the shared
path entirely. I am naming that gap rather than calling three green runs a proof.
