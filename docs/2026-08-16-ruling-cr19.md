# Ruling — CR-19, `emulator/play_input` (2026-08-16)

Un-framed adjudication of `docs/2026-08-16-cr19-pad-timeline.md`. Same mechanism as CR-18's
(`docs/2026-08-16-ruling-cr18.md`).

## Verdict: ADOPT WITH CHANGES — ten, none of which alter the design

Intervals, union, the purity property and the bound all survive. What did not: three of five result keys
(CR-13), the §6 table the row was aimed at, the precision of the purity pin, the 6-button pin's target, and
the fact that a frame-advancing method owes the `stopped` event a story.

## ★ The finding that matters most: both of the CR's corrections stop one step short

The CR's two headline corrections were **verified and are right about what they checked**. Each also stops
exactly one step early, and one of those changes the answer to the CR's own first question.

**Correction 1 stopped at playback; the pain it cites is in recording.** `INPUT_PLAYBACK` really does play
the engine's own in-ROM stream, so injection is not the mechanism there — verified. But `replay.emp` has a
third mode: **`INPUT_RECORD` taps the *latched live* pad** into the record ring, and outside playback that
latched pad is exactly what the emulator's `set_pad` drives. The sibling pain the CR quotes as its
evidence — *"re-recording is impossible"*, ~7 manual playthroughs per re-stamp — **is recording-side**. So
the ARP0 case does not evaporate; it moves from the half the CR examined to the half it did not, and a
deterministic timeline is precisely the re-record instrument.

**"A pad timeline would be inert during a replay run" is overstated.** The playback path reads the **live**
`Ctrl_1_Press` Start bit before overwriting, and sets `Replay_Exit_Request`. Injected Start is not inert —
it aborts the replay. The direction of the correction survives (injection cannot help and can only harm),
but the word does not.

**Correction 2 (one in-tree timeline, not six) — verified exactly**, row for row, including that the
frontend sites are live host input rather than timelines.

**The spike's symbol self-correction — verified independently.** `MDDBG__ErrorHandler =
extern("ErrorHandlerBlob")` (`error_handler.emp:84`) is the common entry; `ErrorTrap` handles the
TRAP/reserved vectors and raises its own error. Addresses confirmed against `s4.debug.lst:4759-4760`. One
anchor was two rows short: the vector rows are `vectors.emp:135–142`, not `135–140`.

## ★ A live divergence the CR walked past

The CR's 6-button pin fingered the MCP's tool description — true, but the smallest of three sites. **The
contract's own §6 `press` row and the schema's `press.buttons` enum both list `x`/`y`/`z`/`mode` as legal**,
while the reference server refuses them with `-32602` on the strength of a `sixButtonPad: false` capability
that **appears nowhere in the contract or schema** (grep: zero hits).

So the server rejects a parameter its own normative schema accepts, justified by a capability key it
invented — a live divergence *plus* a CR-13-class invention, sitting in a shipped method. Pin 4 cannot be
adopted coherently without fixing it in the same stroke.

## What was struck, and on which precedent

| proposed key | verdict |
|---|---|
| `reason` | **struck** — §11.7 cited backwards: the house rule puts the stop condition on the **`stopped` event**, and no catalogued method carries `reason` as a result key |
| `stoppedAt` | **struck** — CR-17 made `frames` exact *precisely* in the watch-cut case, so the stop position is `frames` in every case. This is §11.5's `run_to.stoppedAtFrame`, re-proposed |
| `rowsApplied`, `ports[]` | **struck** — pure functions of `rows` + `frames`; the offence §11.10 struck a per-entry `parsed` flag for |

Result becomes `frames`, `frameToken`, `pc` — `run_frames`' own shape, which is what this method is.

## ★ `press` is not subsumed, and the CR's premise was false

The CR offered to keep `press` for compatibility and called the overlap a smell. The overlap does not
exist: **`press` unions its buttons with the live and held sets by design**; `play_input` suspends both.
With Right held, `press{buttons:["a"]}` taps Right+A while the one-row timeline taps A alone. Different
semantics, not two spellings. Both stay, each row naming the difference.

## The purity property: right, and one input source short

The prose said "of nothing else" while the pinned MUST NOT named only the client's held set. The engine
merges **two** non-row sources — the client's `held[]` *and* the host's `live[]` (a human's physical pad).
A hosted server could union `live` and argue conformance from the letter. It now names both, adds that a
port no row covers is fully released, and pins the application point (boundary before each 0-based,
call-relative frame index).

Union is also ruled **order-independent** — the pad depends on the row *set*, not row order — which is why
"rows need not be sorted" costs nothing, and why later-row-wins was rejected: it would make row order
load-bearing and reintroduce a place two servers silently differ.

## Ruled on the four open questions

1. **Build now.** The CR's self-deflation is overstated (see the recording half). No item-19 violation is
   open, the amendment is additive, and the remaining engine-side link gates nothing in this contract.
2. **Union**, normatively, with "complete button set" reworded to "the buttons the row contributes" —
   under union no single row is complete.
3. **`stoppedAt` struck.**
4. **`press` survives**, on semantics rather than compatibility.

## Also required, and absent from the CR

- **The `stopped` event story**: one `resumed` at start, one `stopped` at end, never per frame;
  `reason: "runFrames"` on completion; and the attribution a timeline-driven stop carries must be ruled
  explicitly rather than left to silence.
- **`maxFrames` ceiling is `max_run_frames`**, not `press`'s legacy 1000 (≈16.7 s — too short for the
  re-record workflow that is now this capability's strongest case).
- **Error pins**: `end <= start`, empty `rows`, over-bound `rows` → `-32602`; and the row bound made
  discoverable via `initialize.limits` rather than learned by hitting it.
- **Adoption condition** per §11.6/§11.8/§11.10 — the fragment is registered when a real reply passes it
  **closed**, both branches, including a watch-cut reply carrying `frames: 0`.
- **D12 stated non-applicable**: not wait-shaped, so no `reached`.
- **Implementation anchor**: the handler loops `Engine::advance(1)`, not bare `run_frames(1)` — the watch
  fan-out and CR-17's exact-frames accounting ride `advance`, and a bare-core loop loses mid-frame
  `stopAfter` stops.

## The lesson, and it is a sharper version of CR-18's

CR-18's lesson was that the register's failure mode is true-sounding claims rather than bad decisions. This
one adds: **a correction can be right and still stop short.** Both of CR-19's corrections were verified —
and one examined the playback path while the evidence it cited lived in the recording path, and the other
objected to a client's promise while the same promise sat unfixed in the contract. Checking a claim is not
the same as checking its scope.
