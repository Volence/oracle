## Goal & scope

Add the two MOVEP ops — the **last common instruction family** — on the proven micro-op framework. MOVEP
transfers the bytes of a data register to/from **alternating (even/odd) memory addresses** `EA, EA+2, EA+4, EA+6`
(the historical 8-bit-peripheral addressing mode). One addressing mode only: `d16(An)`.

- **MOVEP.w** (`MOVEP.w` file, 8065 cases): 2-byte transfer, opmodes **4** (mem→reg) / **6** (reg→mem), 16 cyc.
- **MOVEP.l** (`MOVEP.l` file, 8065 cases): 4-byte transfer, opmodes **5** (mem→reg) / **7** (reg→mem), 24 cyc.

Both files are 100% PURE single-family and **100% in scope — ZERO deferral**: byte-addressed (no odd-EA
alignment faults are possible), no corrupt entries, A7 fully covered (`d16(An)` never predec/postinc). New
threshold **946083** (929953 + 16130).

**No flags** (SR byte-identical initial→final on all 16130 cases). **PC += 4** (2-word instruction).

## Encoding

Opcode `0000 rrr 1 oo 001 aaa`: bits15-12 = `0000`, bits11-9 = `Dn`, bit8 = `1`, bits8-6 = opmode, **bits5-3 =
`001`** (the An-direct EA field — MOVEP's signature), bits2-0 = `An`.

- **Decode key: `(opcode & 0xF138) == 0x0108`.** The mask fixes bits15-12=0000, bit8=1, bits5-3=001.
- **Distinct from the dynamic BTST/BCHG/BCLR/BSET** (which share `0000 rrr 1 tt <ea>` but have EA mode ≠ 001).
  The existing bit-op decode already excludes mode 001 (its comments literally read *"Mode 001 = MOVEP (absent /
  not decoded)"*, decode.rs:477/500/523/542). MOVEP's dispatch fills exactly that carved-out slot. Insert the
  MOVEP check in `decode_dispatch` **before** (or independent of) the bit-op arms — since the spaces are disjoint
  by the mode field, order is not load-bearing, but keep it adjacent to the bit-ops with a comment.
- **Opmode (bits 8-6): bit7 = DIRECTION (0 = memory→register READ, 1 = register→memory WRITE); bit6 = SIZE (0 =
  word, 1 = long).** So: 4 = word mem→reg, 5 = long mem→reg, 6 = word reg→mem, 7 = long reg→mem.
  - ⚠️ The SST `name` field's textual direction reads OPPOSITE the transactions for the read opmodes — **trust the
    opmode bits / the transaction kinds (`r`/`w`), not the name string.**

- **EA = `(An + sign_extend16(d16)) & 0xFFFFFF`**, where `d16` = the extension word = `regs.prefetch[1]`.
  IDENTICAL to the `d16(An)` addressing mode — reuse `compute_ea`/the `EaCalc{base:AddrReg(an), index:Zero,
  disp:DispWord, dst:EA_SLOT}` shape verbatim (ea.rs:924-939, the mode-5 leg). A7 → SSP (all supervisor); in
  scope (no SSP mutation — `d16(An)` is not auto-inc/dec).
- **Byte order = big-endian over the alternating addresses `EA, EA+2, EA+4, EA+6`:**
  - **reg→mem word**: write `(Dn>>8)&0xFF`@EA, `Dn&0xFF`@EA+2.
  - **reg→mem long**: write `(Dn>>24)&0xFF`@EA, `(Dn>>16)&0xFF`@EA+2, `(Dn>>8)&0xFF`@EA+4, `Dn&0xFF`@EA+6.
  - **mem→reg word**: `Dn = (Dn & 0xFFFF_0000) | (mem[EA]<<8) | mem[EA+2]` — **HIGH WORD PRESERVED.**
  - **mem→reg long**: `Dn = (mem[EA]<<24) | (mem[EA+2]<<16) | (mem[EA+4]<<8) | mem[EA+6]` — full 32-bit overwrite.
- **Flags: none.** `final.sr == initial.sr` on all 16130.
- **Timing: UNIFORM.** MOVEP.w = 16, MOVEP.l = 24 (single addressing mode → no per-mode variation).
- **PC = initial pc + 4.** All other registers unchanged (mem→reg touches only `Dn`; reg→mem touches only memory).

### The one novel shape — the byte-scatter bus stream (uniform across all 4 variants)

```
r  pc+4  .w  (fc6, program)   ← refill prefetch, value → final.prefetch[0]
<N byte accesses at EA, EA+2, EA+4, EA+6>   (fc5, data, .b; READ if mem→reg, WRITE if reg→mem)
r  pc+6  .w  (fc6, program)   ← final prefetch,  value → final.prefetch[1]
```

N = 2 (word) / 4 (long). **The refill prefetch is FIRST (before the byte accesses); the final prefetch is LAST.**
Transaction tuple = `[kind, 4, fc, addr, size, value]`. Each byte access = 4 cyc, each prefetch = 4 cyc → word =
4+2·4+4 = 16, long = 4+4·4+4 = 24. ✓

## Recipe design — the MOVEM precedent (byte-sized, +2 stride)

MOVEP is a running-address-in-scratch, decode-time-expanded, stepped multi-transaction transfer — the **byte
cousin of MOVEM** (`MovemStore`/`MovemLoad`, microop.rs:1209/1230). Model the new ops directly on those.

**New vocab (two MicroOps, mirroring MovemStore/MovemLoad):**

| MicroOp | Semantics | Cycles / bus |
|---|---|---|
| `MovepStore { dn: u8, shift: u8, addr_slot: Slot }` | write `((regs.d[dn] >> shift) & 0xFF)` as a **byte** at `scratch[addr_slot]` (Fc::Data), then `scratch[addr_slot] += 2` | 4 cyc, one `w .b` txn |
| `MovepLoad { dn: u8, shift: u8, addr_slot: Slot }` | read a **byte** at `scratch[addr_slot]` (Fc::Data), merge `regs.d[dn] = (regs.d[dn] & !(0xFF << shift)) \| ((byte as u32) << shift)`, then `scratch[addr_slot] += 2` | 4 cyc, one `r .b` txn |

- The **merge** semantics make word vs long fall out for free: word loads at shifts `[8, 0]` (high word of Dn
  preserved); long loads at `[24, 16, 8, 0]` (all four bytes overwritten). Same shift lists drive the stores.
- No new `Operand` — the running-addr-in-scratch self-advance (exactly MOVEM's `addr_slot += size`) handles the
  stride; MOVEP's stride is the constant `2` (byte value at `addr`, next byte at `addr+2`).
- Address masking / FC follow the existing bus path (byte access → no alignment fault ever). `regs.d[dn]` for the
  merge is a plain data register (no A7 aliasing — MOVEP's register operand is always a **data** register).

**`movep_recipe(opcode, regs)`** (shared by both commits, size-parameterized):

```
let dn, an, opmode from opcode; let (mem2reg, nbytes) from opmode;   // nbytes = 2 (word) / 4 (long)
EaCalc { base: AddrReg(an), index: Zero, disp: DispWord, dst: EA_SLOT }   // EA = An + sx16(d16), BEFORE the refill
Prefetch                                                                  // refill @ pc+4
for k in 0..nbytes:
    let shift = 8 * (nbytes-1 - k);          // word → [8,0]; long → [24,16,8,0]
    if mem2reg { MovepLoad  { dn, shift, addr_slot: EA_SLOT } }
    else       { MovepStore { dn, shift, addr_slot: EA_SLOT } }
Prefetch                                                                  // final @ pc+6
```

Op count: word = 1+1+2+1 = 5; long = 1+1+4+1 = 7 (≤ `MAX_OPS` 40). `EA_SLOT` reused as both the EA and the
running pointer (the `+= 2` self-advance walks it). No `SCRATCH_SLOTS` change.

## Risks / watch-items

- **The refill/byte/prefetch ORDER is load-bearing** — the refill prefetch precedes the byte accesses; the final
  prefetch trails them. A recipe that emits the byte accesses before the first Prefetch will mis-order the
  transaction stream (only the per-cycle transaction gate catches this; the cycle *count* is order-independent).
- **`EaCalc` must run before the first `Prefetch`** — `d16` lives in `prefetch[1]` and the refill shifts it out
  (the same constraint as every `d16(An)` mode; the mode-5 EA leg already handles it).
- **mem→reg word must PRESERVE Dn's high word** — the merge `& !(0xFF<<shift)` at shifts 8/0 does this; do NOT
  zero the register first. mem→reg long overwrites all four bytes (shifts 24/16/8/0 cover the whole register).
- **The register operand is a DATA register** (`regs.d[dn]`), never A7 — no addr-reg aliasing in the merge/scatter.
- The novel MicroOps must **self-book their 4 cycles** if they early-return from `exec_one` (check the MOVEM
  precedent's cycle-booking path) — otherwise mirror the standard Read/Write tail.
