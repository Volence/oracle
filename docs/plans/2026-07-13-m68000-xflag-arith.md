## Goal & scope

Add the **X-flag arithmetic cluster** on the proven micro-op framework. All 9 ops share three traits that make this
one coherent family: an **incoming X flag** that participates in both the value and the carry, a **STICKY Z**
(`Z_final = Z_in AND result==0` — the multi-precision idiom already implemented for `AluOp::Negx`), and (for the
non-NBCD ops) the **`Dn,Dn` / `-(Ay),-(Ax)` two-address encoding** (`M = bit 3`). All 9 SST files are 100% PURE
(one family each, 8065 cases). `MAX_OPS` is already 40 (from MOVEM) — **no structural change**; this push is ALU +
recipe work reusing the ADD/SUB/NEG machinery, the `-(An)` predecrement addressing, and the E3/E4 address-error abort.

| Op | Opcode / mask | Semantics | Flags |
|---|---|---|---|
| **ADDX.b/.w/.l** | `0xD100`, mask `0xF130`, size≠3 | `Dx = Dx + Dy + X` / `-(Ax) = -(Ax) + -(Ay) + X` | X,N,Z(sticky),V,C |
| **SUBX.b/.w/.l** | `0x9100`, mask `0xF130`, size≠3 | `Dx = Dx − Dy − X` / predecrement twin | X,N,Z(sticky),V,C |
| **ABCD** | `0xC100`, mask `0xF1F0` | `Dx = Dx +₁₀ Dy + X` (BCD) / predecrement twin | X,N*,Z(sticky),V*,C |
| **SBCD** | `0x8100`, mask `0xF1F0` | `Dx = Dx −₁₀ Dy − X` (BCD) / predecrement twin | X,N*,Z(sticky),V*,C |
| **NBCD** | `0x4800`, mask `0xFFC0` (data-alterable) | `<ea> = 0 −₁₀ <ea> − X` (BCD negate) | X,N*,Z(sticky),V*,C |

`M = bit 3` selects the two-address form: **M=0 → `Dy,Dx`** (data-register direct, no memory), **M=1 →
`-(Ay),-(Ax)`** (memory predecrement). `Rx = (op>>9)&7` (destination), `Ry = op&7` (source). NBCD is single-operand
over the standard data-alterable EA range. **(`N*`/`V*`: "undefined" in the manual but fully deterministic on the
68000 — the SST captures the real chip, so we model them exactly; see below.)** Every op sets **X = C**.

**Opcode-space notes (mode-guard against the ADD/SUB/AND/OR/NEG neighbours).** ADDX/SUBX/ABCD/SBCD live in the
`ADD`/`SUB`/`AND`/`OR` opcode spaces, in the `Dn,<ea>`-direction slots whose `<ea>` mode field = 000 (`Dn`) or 001
(`An`) — both illegal as a real destination for those ops, so the ISA repurposes them. Classify by the exact masks:
- **ADDX** `(op & 0xF130) == 0xD100` **and** `(op>>6)&3 != 3` (size 3 = `ADDA`). The mask fixes bits 15-12=`1101`,
  bit 8=1, bits 5-4=00 — leaving size (7-6), M (3), Rx, Ry. The ADD decode arm must never match ea-modes 000/001 in
  the to-`<ea>` direction (it already can't — you cannot ADD into `Dn`/`An` via that path). **SUBX** `== 0x9100`.
- **ABCD** `(op & 0xF1F0) == 0xC100`; **SBCD** `(op & 0xF1F0) == 0x8100`. The `0xF1F0` mask fixes bits 15-12, bit 8,
  bits 7-4=0000 (byte size + bits 5-4=00) — leaving M (3), Rx, Ry. Disjoint from **EXG** (`0xC140`/`0xC148`/`0xC188`,
  opmode bits 7-3 ∈ {0x08,0x09,0x11}) and from real `AND.b`/`OR.b Dn,<ea>` (whose ea modes 2-7 give bits 5-4 ≠ 00).
- **NBCD** `(op & 0xFFC0) == 0x4800`, data-alterable modes only. Sits in the `0x4x00` unary column beside
  `NEGX 0x4000` / `CLR 0x4200` / `NEG 0x4400` / `NOT 0x4600` / `TAS/TST 0x4Axx` — its own `0x4800` slot, no collision.

## Recon findings (exhaustive, 0-mismatch — `scratchpad/xflag_recon/final.py`)

**All 9 files, every clean case: 0 mismatches** on value + all 5 CCR bits. Full detail in the `recon-xflag` memory.
Common: `X_in=(sr>>4)&1`, `Z_in=(sr>>2)&1`; **X_out = C_out**; **N = msb(result)**; **Z is STICKY**
(`Z_final = Z_in AND result==0` — cleared if result≠0, else unchanged; never SET).

### ADDX / SUBX — binary arithmetic, standard overflow
- **ADDX**: `raw = dst + src + X_in`; `res = raw & mask`; **C = (raw > mask)**; **V = msb(~(dst^src) & (dst^res))**.
- **SUBX**: `raw = dst − src − X_in`; `res = raw & mask`; **C = (raw < 0)** (borrow); **V = msb((dst^src) & (dst^res))**.
- These are the ADD/SUB ALU with an incoming X folded into the sum/difference and the sticky-Z override.

### ABCD / SBCD / NBCD — decimal correction (empirically fit, 0-mismatch)
- **ABCD** (`dst +₁₀ src + X`): `binary = dst + src + X_in`; `lowc = 6 if (dst&0xf)+(src&0xf)+X_in > 9 else 0`;
  **C = X = (binary > 0x99)**; `res = (binary + lowc + (0x60 if C else 0)) & 0xff`; **V = msb(res & ~binary)**.
- **SBCD** (`dst −₁₀ src − X`) — **carries a REAL carry/result ASYMMETRY (28 divergent cases, load-bearing):**
  `binary = dst − src − X_in`; `lowc = 6 if (dst&0xf)−(src&0xf)−X_in < 0 else 0`;
  - **C = X = ((binary − lowc) < 0)** — the borrow flag keys on `binary − lowc`.
  - **`highc = 0x60 if binary < 0 else 0`** — the result's high correction keys on `binary` **(NOT `binary − lowc`)**.
  - `res = (binary − lowc − highc) & 0xff`; **V = msb(~res & binary)**.
  - The 28 divergent cases: small-positive `binary` (1..5) with a strongly-negative low nibble (`lowc=6` drags
    `binary−lowc` negative) → **C=1 but no 0x60 result correction**. A single shared condition is WRONG; the impl
    MUST compute the two conditions separately. Pin an anchor from this set (e.g. `dst=0xf0, src=0xef, X=0` →
    `res=0xfb, C=X=1, V=0, N=1`).
- **NBCD** (`0 −₁₀ dst − X`) = **exactly `sbcd_core(0, dst, X_in)`** (0-mismatch — reuse the SBCD core with `src=0`,
  operand as `dst`). Byte-only single-operand over the data-alterable EA. **Byte access never faults.**

### Timing (0-mismatch, all modes)
- **ADDX/SUBX** `Dn,Dn` = **4** (.b/.w) / **8** (.l); `-(An),-(An)` = **18** (.b/.w) / **30** (.l).
- **ABCD/SBCD** `Dn,Dn` = **6**; `-(An),-(An)` = **18**.
- **NBCD** `Dn`=6, `(An)`=12, `(An)+`=12, `-(An)`=14, `d16(An)`=16, `d8(An,Xn)`=18, `abs.w`=16, `abs.l`=20
  (= 6 for reg, else 8 + the EA-calc idle).
- **Address-error faults** (`-(An),-(An)` word/long, odd predecremented address — IN scope via E3/E4): length **52**
  (fault on src read) / **56** (.w, fault on dst read) / **60** (.l, fault on dst read). Produced by the existing
  abort — not separately modeled.

## The mechanism

**Reuse:**
- **The ALU flag path + sticky-Z template.** `AluOp::Negx` already implements *incoming-X + sticky-Z*
  (`microop.rs` ~L1710): `X_in`/`Z_in` from SR, `Z_final = Z_in AND res==0`. ADDX/SUBX/ABCD/SBCD/NBCD add
  dedicated `AluOp` variants that follow this same "recompute-with-X, sticky-Z" shape (they are NOT `Add`/`Sub`
  delegations — they carry the incoming X and the sticky Z, exactly like `Negx` is dedicated).
- **The single-EA data-alterable RMW** (NBCD) — the same read-modify-write EA machinery as `NEG`/`NOT`/`NEGX`
  (`<ea>` operand read → ALU → write back), with the NBCD idle profile per the timing table.
- **`-(An)` predecrement addressing + the E3/E4 address-error abort** — the two-operand predecrement RMW is new in
  *shape* (two reads then a write) but reuses the predecrement step, the odd-address group-0 abort, and the
  predecrement-commits-before-the-faulting-access ordering (the same rule MOVEM `(An)+` used).

**New — the two recipe shapes (C0, reused C1–C2):**
1. **Register-direct X-arith** (`M=0`): read `Dy` and `Dx` at size → the dedicated `AluOp` (Addx/Subx/Abcd/Sbcd) →
   write `Dx`. Length 4/8 (ADDX/SUBX) or 6 (ABCD/SBCD). `[…, Prefetch]` + the internal idle that sets the length
   (the register forms have an extra internal cycle vs. a plain ADD `Dn,Dn` — pin against the data).
2. **Two-operand predecrement RMW** (`M=1`, `-(Ay),-(Ax)`): **predec `Ay` by size → read src @ Ay → predec `Ax`
   by size → read dst @ Ax → ALU → write result @ Ax → prefetch.** `-(A7).b` steps by **2**. **Same-register
   (`rx==ry`)**: the second predecrement decrements the already-decremented value, so src @ `A−size`, dst @
   `A−2·size`, final reg = `A−2·size` — the running pointer must be a single register decremented twice in
   sequence (do NOT compute both from the initial value). Odd-address faults fall out of the existing abort on the
   first odd access, with the predecrement(s) committed per the fault table above (src-odd → only Ay committed,
   length 52; dst-odd → both committed, length 56/60).

**NBCD (C3):** single data-alterable EA (`Dn`, `(An)`, `(An)+`, `-(An)`, `d16(An)`, `d8(An,Xn)`, `abs.w`, `abs.l`)
→ `AluOp::Nbcd` (= `Sbcd` core with the operand as `dst`, `src=0`) → write back. Standard unary RMW; byte-only so no
alignment fault. `-(A7).b` steps by 2; `(A7)+`/`-(A7)` are IN scope (like the other byte unary ops).

## Risks
- **The SBCD carry/result asymmetry.** The single easiest bug: using one condition for both the flag and the result.
  They differ in 28 cases — pin the anchor and compute them separately.
- **BCD undefined N/V.** They are deterministic on the 68000 and the SST asserts them; the fitted formulas above are
  0-mismatch — do not "simplify" to a plausible-but-wrong overflow rule.
- **Same-register `-(An),-(An)` sequential predecrement.** Computing both operand addresses from the initial An is
  wrong for `rx==ry`; the pointer must decrement twice in sequence (final reg = `A − 2·size`).
- **`-(A7).b` step of 2.** Byte predecrement of A7 steps by 2 (stack alignment) — for ADDX/SUBX/ABCD/SBCD/NBCD.
- **Odd-address fault register-commit + timing.** src-odd → only Ay committed (len 52); dst-odd → both committed
  (len 56/60). Mirror the E4 predecrement-before-fault ordering; the abort produces the frame + timing.
- **ADDX/SUBX are NOT ADD/SUB with a delegate.** Like `Negx`, they must be dedicated ALU ops carrying the incoming
  X into the value AND the carry, plus the sticky Z — a `Cmp`/`Sub` delegation drops the X and the sticky Z.
