# Push A / A3 plan: the trace exception (vector 9)

**Status: PLANNED 2026-07-15.** Implements slice A3 of the Push-A exception cluster
(`docs/decisions/2026-07-15-push-a-exception-cluster-plan.md`): the T-bit trace facility and the
first real `begin_next` priority dispatch (trace outranks a decode-time exception / a pending
interrupt). No SST data covers this cluster (audit finding 3) — driven by hand-authored vectors on
both drivers, recon pinned from `docs/reference/` (Yacht.txt v1.1 + M68000UM §6.3.8) with the one
documented divergence (STOP×trace) resolved by BlastEm-over-the-bus per the ratified tiebreak.

## Why A3 is the architecturally interesting slice

Until now `step()` has been a thin fast path: decode `prefetch[0]`, run it, apply a completed STOP.
A3 gives `begin_next` its **first two event classes to order** — a boundary event (trace) vs. a
decode-time exception — so the priority dispatch stops being speculative. The ordering is pinned,
not emergent from implementation order (M68000UM §6.2.3 group-1 priority + §6.3.8).

## Recon — PINNED from `docs/reference/` (Yacht L1548 + M68000UM §6.3.8)

### Timing + bus stream (Yacht L1548)
Trace = **34(4/3)**, stream `nn ns nS ns nV nv np n np` — **byte-identical timing** to the decode-time
exceptions (privilege/illegal, L1550/1551, both 34(4/3)); the leading `nn` = `Internal{4}`, the
trailing `n` = the `n2` inside `vector_fetch_and_reload`. Cycle check: 4 + 3·4(writes) + 2·4(vector) +
2·4(reload) + 2(n2) = 34. ✓

### The load-bearing difference: write order + stacked PC
- **Write order** differs from the decode-time frame. Yacht legend (L141/142): `s` = push LSW,
  `S` = push MSW. Decode-time (L1550/1551) middle = `ns ns nS` = `s s S`; Trace (L1548) = `ns nS ns`
  = `s S s`. Both leave the **identical final frame** (M68000UM Fig 6-5: `SR @ SSP+0`, `PCH @ SSP+2`,
  `PCL @ SSP+4`) — only the on-bus temporal order of the three writes differs:
  - decode-time (`push_standard_frame`): PCL @ B+4, **SR @ B+0**, PCH @ B+2.
  - trace (**new** `push_trace_frame`): PCL @ B+4, **PCH @ B+2**, SR @ B+0 (the two PC halves
    back-to-back, SR written last).
- **Stacked PC = the address of the NEXT instruction** (M68000UM §6.3.8: *"The saved value of the
  program counter is the address of the next instruction"*), NOT `pc+0` like privilege/illegal. Trace
  fires *after* the instruction completes, so at the service point `regs.pc` already = the next
  instruction's first word (the queue-head invariant). So `TargetCalc(PcPlus(0))` captures it — the
  same op as the decode-time recipe, but its value is now the next-instr address by timing, not the
  faulting one.
- **Vector 9** (`0x024`, supervisor-data, FC=5 fetch) — M68000UM Table 6-2.

### Behavioral rules (M68000UM §6.3.8, PDF p.100-101 — verbatim-pinned)
- **T sampled at instruction START**: *"If the T bit is set (on) at the beginning of the execution of
  an instruction, a trace exception is generated after the instruction is completed."* → latch T
  **before** decode; the instruction may change SR (MOVEtoSR/RTE/ANDItoSR) — the *latch* decides, not
  the post-instruction T. So: an instruction that **clears** T still traces (latch was set); one that
  **sets** T does **not** trace this instruction (latch was clear) — it traces after the *next* one.
- **Suppression set**: *"If the instruction is not executed because an interrupt is taken or because
  the instruction is illegal or privileged, the trace exception does not occur. The trace exception
  also does not occur if the instruction is aborted by a reset, bus error, or address error."* →
  suppress after: **illegal / line-A / line-F / privilege** (decode-time) and **address/bus error**
  (fault). Do NOT suppress after an *executed* instruction that itself traps (TRAP/TRAPV/CHK/div0).
- **Sequencing**: *"if an exception is forced by that instruction, the exception processing for the
  instruction exception occurs before that of the trace exception"* + the TRAP example (*"First, the
  trap exception is processed, then the trace exception, and finally the interrupt exception"*). So a
  TRAP with T set stacks the trap frame **then** a trace frame — trace is *sequenced after*, not
  suppressed. **This falls out for free** from the marker design below (TRAP recipes are not marked
  `suppresses_trace`, so the post-TRAP `regs.pc` = handler start gets traced — UM-correct).
- **Trace > interrupt**: pinned for A4 (*"the trace exception is processed before the interrupt"*).

## Design

### `suppresses_trace` marker (correct-by-construction)
Add a serialized `suppresses_trace: bool` to `MicroState` (getter for the orchestrator). Set it in the
recipes that represent *"the instruction did not execute / was aborted"*:
- `decode_time_exception_recipe` (illegal v4 / privilege v8 / line-A v10 / line-F v11) → **set**.
- the address-error install (`build_address_error_frame`) → **set**.
- Everything else — normal instructions AND the executed traps (`trap_recipe`, CHK/div0/TRAPV
  installs) — leaves it `false`, so trace fires after them (TRAP-then-trace, UM-correct sequencing).

### `begin_next` — the latched-field dispatch
Add a serialized `trace_pending: bool` to `Cpu68000`. `step()` becomes the priority decision point
(one serviced unit per call — the begin_next shape A4 extends):
```
if self.trace_pending {                    // (A4 will add: else-if interrupt)
    self.trace_pending = false;
    return trace_exception_recipe().run_to_completion(&mut regs, bus);
}
let trace_arm = (regs.sr & SR_TRACE) != 0; // latch T BEFORE decode
let mut recipe = decode(&regs);
let suppress = recipe.suppresses_trace();
let cycles = recipe.run_to_completion(&mut regs, bus);
if recipe.requests_stop() { self.state = Stopped; }
if trace_arm && !suppress { self.trace_pending = true; }  // service on the NEXT begin_next
cycles
```
`trace_exception_recipe()` mirrors `decode_time_exception_recipe` but with `push_trace_frame` +
vector 9: `[TargetCalc(PcPlus(0)), EnterException, Internal{4}, push_trace_frame, vector_fetch_and_reload(9*4)]`.

### Vocabulary added
- `exception.rs`: `push_trace_frame(buf, saved_pc_slot, save_sr_slot)` — the `s S s` write order.
- `decode.rs`: `trace_exception_recipe()` (or fold vector+frame-shape into a shared helper).
- `microop.rs`: `MicroState::suppresses_trace` field + getter; `Cpu68000::trace_pending` field.
- No new `MicroOp` variants (EnterException already clears T; TargetCalc/frame/vector reused).

## Slicing (small commits, each self-verified)

### A3.1 — core trace (fully §6.3.8-pinned)
`push_trace_frame` + `trace_exception_recipe` + the `suppresses_trace` marker + the `begin_next`
latched dispatch. Hand vectors for the matrix rows that §6.3.8 fully determines:
- **plain** instruction × {T=0 → no trace; T=1 → trace, stacked PC = next instr, `s S s` order}.
- **SR-modifying** (MOVEtoSR clearing T / ANDItoSR / RTE) × {latch was set → still traces; latch
  clear → no trace even if the new SR sets T}.
- **decode-time trap** (illegal, privilege) × T=1 → **no trace** (suppressed; the trap frame only).
Both drivers, snapshot/restore at every boundary, priority test (trace serviced before the next
decode). SST 1,000,058 stays green (the gate never sets T on a vendored case — supervisor,
T=0 throughout; `step()` is not on the SST path). Timing: BlastEm-over-the-bus cross-check of the
34(4/3) stream (the `n`-idle placement is asserted only in aggregate, per the harness note).

**Pin the distinction itself, not just the trace stream** (owner's addition): a unit test runs
`push_trace_frame` and `push_standard_frame` *side by side* on the same seed and asserts their
transaction streams differ **exactly** in the `s S s` vs `s s S` write positions (identical
addresses/values, permuted order). The end-state layout is identical by design, so without this a
future refactor could silently collapse one builder into the other; this test makes that a failure.

### A3.2 — the STOP × trace cell (one behavioral fork to resolve)
STOP uniquely **modifies SR (T) as its effect, before its own stop/trace decision**, so §6.3.8's
uniform "T at instruction start" rule is ambiguous for it. The sources conflict:
- M68000UM §6.3.8 (uniform rule) ⇒ the **start** T (old T, before STOP loads the immediate).
- M68000PRM STOP description + the owner's pin ⇒ the **loaded** SR's T (the immediate's T bit) — STOP
  *"traces rather than stops"* when the new SR has T set.
These diverge exactly on *"T only in the loaded immediate, clear before"*. **Resolve by
BlastEm-over-the-bus differential** (the ratified tiebreak where UM/Yacht are silent/conflicting —
NEVER BlastEm's source), with the owner's loaded-SR-T as the hypothesis to confirm.

**Sweep the full 2×2, not just the headline cell** (owner's addition): there are TWO T bits in play —
T at STOP's start (old SR) and T in the loaded immediate — so four cases, and the sources diverge on
more than the one cell (old-T=1 also raises: does it trace after loading? which PC stacks? does the
CPU end `Stopped`?). Per cell, observe **three things over the bus**: (a) whether a trace frame
appears, (b) the stacked PC, (c) the final CPU state (`Normal`/handler vs `Stopped`). Four differential
runs settle the entire ambiguity empirically at once; then wire the confirmed rule — a traced STOP
services the trace **instead of** lingering `Stopped` (trace preempts the stop; don't set both
`Stopped` and `trace_pending`). Kept a separate commit precisely because its pin is a differential,
not an in-tree citation.

## Anti-cheating / invariants
- SST is ground truth and untouched — `step()`/`trace_pending` are off the vendored path; the gate
  must stay at exactly 1,000,058, re-run before each commit.
- `#[must_use]`-hardened EA builders (A2b) unaffected.
- Behavioral facts pinned from `docs/reference/` only; the single differential (STOP×trace) is
  labelled as such and cross-checked against hardware behavior over the bus, never emulator source.

## Risks
- **Queue-head PC invariant**: the trace stacked PC relies on `regs.pc` = next-instr address after a
  clean completion. Verify against a plain-instruction vector before trusting it for the frame.
- **`push_trace_frame` write order**: the `s S s` vs `s s S` distinction is the whole point — pin the
  three write addresses/order against the Yacht stream in a dedicated frame test, not just the
  end-state layout (which is identical to the standard frame).
- **STOP×trace preemption**: don't set `Stopped` and `trace_pending` both — the traced STOP must not
  linger Stopped. Handled in A3.2 with the differential-confirmed rule.
