# K4-0 — open-bus blast-radius measurement (2026-08-02)

The slice-gating deliverable of `docs/2026-08-02-k4-openbus-design.md` §5: every 68k read whose value
would change under the K4 rules (or whose count gates a slice's risk), classified per ROM by
`crates/oracle-core/examples/k4_openbus_probe.rs` (zero `src/` changes — a pure `BusEventSink`
consumer). Re-run any time with `cargo run --release -p oracle-core --example k4_openbus_probe`.

| column | meaning | gates |

| `1100` / `1100R!` | `$A11100-1` reads / of those, while Z80 reset asserted (STOP (b)) | K4-2 |
| `zcR!` / `zcW!` | Z80-window reads / writes while the window would be closed (STOP (b)) | K4-3 |
| `zw!` | open-window word reads whose two bytes differ (→ even-byte duplication) | K4-3 |
| `bank` | open-window reads in `$A06000-$A07EFF` (→ `$FF`) | K4-3 |
| `ioE` / `ioW` | `$A10000-$A1001F` even-byte reads / word reads | K4-4 |
| `st` / `stO` | `$C00004-7` word+even-byte reads / odd-byte reads (unaffected) | K4-5 |

## Adjudication per slice

- **Currencies frozen-by-construction, measured:** the gate fixture (the exact
  `determinism_gate`/`export_state_v1` workload) touches **zero** K4-affected addresses (the probe
  asserts this). `golden_frames`/`oracle_differential` don't drive the 68k bus at all.
- **K4-1 (`$400000-$7FFFFF` + `$A11200`):** only `m68k_memory_test` ever touches either. Zero risk.
- **K4-2 (`$A11100` residue + reset-folded bit):** `1100R!` (STOP condition (b), first clause) fires
  **once**, in ristar. Instruction-level adjudication (watch_probe + disassembly): ristar's driver-load
  routine asserts BUSREQ at `$63D6` and polls at `$63E0` with `btst #0,($A11100).l / dbeq d0,·` —
  a **bounded 16-iteration poll** that falls through when the grant never comes. That code shape exists
  *because* hardware reads "unavailable" while reset is asserted (the very semantic K4-2 adds); worst
  case is 15 extra poll iterations, no hang possible. Ristar's only unbounded grant spin (`$250`,
  `btst d0,(a1) / bne`) runs one instruction *after* it releases reset (`$24E`) — unaffected by the
  reset fold. Every other ROM's `$A11100` reads happen with reset released (`1100R!` = 0).
  **Proceed, with a ristar (+ gunstar) boot A/B after the slice.**
- **K4-3 (Z80 window gating):** `zcR!`/`zcW!` = **0 for every game and every test ROM except memtest
  itself** — no corpus ROM reads *or writes* the window without holding BUSREQ with reset released.
  `zw!`/`bank` likewise memtest-only. The highest-risk slice measured as zero-risk on this corpus.
- **K4-4 (I/O even-byte mirror):** `ioE` = 0 everywhere outside memtest. The ubiquitous `ioW` = 3 is
  the classic boot-time `tst.w ($A10008).l`-family control-register check (verified on sonic3k: PCs
  `$20A`/`$212`, f0, value `$0000`) — the registers are still zero at that instant, and `$00`
  mirrored onto both lanes is byte-identical `$0000`. Zero observable change for the corpus.
- **K4-5 (`$C00004` upper-6 residue):** `st` is huge everywhere (vblank-poll idioms; TF4 677k) —
  *counting* cannot prove flag-consumption either way (the STOP (b) third clause is structurally
  unobservable from the bus stream, as the design's §6 Q3 anticipated). Per the design: land K4-5
  **last**, adjudicate by scorecard + game-corpus render/PC A/B against the baselines captured this
  session (boot_rom anchors: s2rev01\@500f, sonic3k\@900f, tf4\@900f, gunstar\@420f/900f,
  batman\@420f/900f, alien\@900f, ristar\@900f, vectorman\@15f/20f).
